# Implementation plans

Use this directory for work that spans multiple files, has meaningful unknowns,
or benefits from explicit checkpoints. Small, obvious changes do not need a plan.

Name plans `YYYY-MM-DD-short-topic.md` and keep them concise:

```markdown
# Topic

## Outcome

One sentence describing the user-visible result.

## Constraints

- Important boundaries, compatibility needs, and non-goals.

## Steps

- [ ] Concrete, verifiable step.

## Verification

- Commands or manual checks that prove the outcome.
```
